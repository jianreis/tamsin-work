# Summary

NN/g's qualitative usability study of customer-service and Messenger/SMS
chatbots (8 participants, mobile and desktop). The findings that matter for a
WhatsApp scripting channel: bots work when they run simple linear flows and
fall over the moment users deviate; users want low interaction cost (few
steps, little reading); and a bot should be honest about being a bot and
narrow about what it can do. The design guidance points the same way as
Google's: reduce steps, keep turns short, support the escape hatches users
actually take (free text, asking for a person).

# Key claims

- Chatbots in the study guided users through **simple linear flows** and had
  a hard time whenever users **deviated** from those flows; flows worked best
  when the bot could absorb unexpected input and use prior context.
- Users engage in **multistep iteration** because the system can only guess
  intent, so each extra option or step multiplies effort; the study frames
  poor designs as imposing high **interaction cost**.
- Participants preferred bots that were **upfront about being non-human** and
  had a **clear, narrow purpose**; users dropped conversational politeness
  with bots and just wanted the task done.
- Design guidance from the study: avoid functions the channel cannot do well,
  reduce the number of steps and the cognitive load per step, communicate
  capabilities early, structure responses, employ **conversation repair**,
  and introduce complexity gradually rather than all at once.
- Chatbots were judged most useful for **repetitive simple tasks** - which is
  what a repeat-collection flow is, provided each exchange stays simple.
